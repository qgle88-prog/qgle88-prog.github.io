## 为什么要做这个

周报和实验记录是那种「每次都要写、每次都写得不一样」的东西。
没有模板的时候，人很容易滑向安全但无用的表达——「效果良好」「继续推进」。

这两份模板的每一栏，都是为了堵住一类具体问题。

## 模板一：周报

核心是**结论前置**。汇报对象通常只读完第一段，把「结果是什么、卡在哪、需要谁做什么决策」
放在最前面，后面才是过程。

其余几栏：

- **状态用 ✅ / 🔄 / ⏸ 三档**，不用「基本完成」这种无法判断的说法
- **数据必须带单位和样本量**，「效果不错」不写
- **风险单独一张表**，写清影响、方案、需要谁支持——把求助显性化

## 模板二：实验记录

核心是**半年后你还看得懂**。当时觉得理所当然的细节，事后全是谜。

关键的两栏：

- **「与上次相比的改动」** —— 结果对不上的时候，九成的原因藏在这里。没有就老老实实写「无」
- **「数据不支持什么」** —— 只写支持的部分，等于给自己埋雷

另外还有「异常与偏差」一张表。只记成功的实验，等于没做实验。

## 为什么是 Markdown

纯文本，Git 能看 diff，知道哪一版改了什么；不绑工具，Typora / Obsidian / VS Code
都能直接打开；需要交 Word 的时候 `pandoc` 转一下，不用重排。

```bash
pandoc 周报模板.md -o 周报.docx
pandoc 实验记录模板.md -o 实验记录.pdf --pdf-engine=xelatex -V CJKmainfont="PingFang SC"
```

## 包里有什么

- `周报模板.md`
- `实验记录模板.md`
- `README.md` — 含转换命令和设计说明

每份模板末尾都有一段 HTML 注释形式的**自查清单**，发出去之前过一遍。
